# DingoNet v0.1 whole-release review

**Scope**: tag `v0.1.0` = `b815b9e` (HEAD `734a982` differs only in docs). `include/DingoNet/`, `src/` (incl.
`Platform/WinSocket.cpp`, `PosixSocket.cpp`), `steam/`, `tests/`, `premake5.lua`, `scripts/`, `.github/workflows/`.
Focus: cross-module behaviour, contracts in `CLAUDE.md` checked against code end to end, Windows/Linux divergence,
and what a second game would hit. Headstone (`main`, `--dingonet`) read only for how it uses the API.

**Baseline**: `scripts\windows\Test.bat Release` and `scripts/linux/Test.sh Release` (WSL2 Ubuntu-24.04) both pass,
62/62. Probes in the scratchpad (`probe.cpp`): a fake transport with `SteamTransport`'s semantics (silent
`Disconnect`, 1 s ignore window, a returning SteamID re-announced as `Connected`) driven by two `Session`s on a fake
clock; a fixed-port re-listen after a TCP session on Windows; 60 host `Stop()`s over TCP while a Windows client streams.

Findings: 1 High, 2 Medium, 7 Low.

## F1 — High — A Steam client the host timed out stays "connected" forever
`src/Session.cpp:405-411`, `src/Session.cpp:461-470`, `steam/SteamTransport.cpp:212-218`, `steam/SteamTransport.cpp:191-201`

Scenario: over Steam, a client's game hitches for more than `Timeout` (a long synchronous load, a debugger stop) or
its upstream drops while the host's packets still reach it. The host drops the seat with `DropPeer(TimedOut)`, which
sends nothing, and `SteamTransport::Disconnect` is silent on the wire by design. The client resumes, reads the host's
buffered pings (`LastHeard` = now) and keeps pinging. One second later the host transport re-announces the SteamID as
a new connection, the host session holds it as an unseated peer and answers its `Ping` with a `Pong` (the Ping case
has no seat check), so the client's `LastHeard` stays fresh and its `Timeout` never fires; the host's handshake
timeout drops and re-creates the unseated peer every ~6 s.
Wrong result: the client never gets `Lost`; `Connected()` stays true, its game input is dropped as unseated. Probe:
host `Left(TimedOut)` at t=5.3 s, then 60 s later the client is still `Connected()` in slot 1 (host churned the
unseated peer 8 times). TCP and Loopback are not affected (their `Disconnect` closes the link).
Fix: answer `Ping` only from seated peers on the host, and send `Bye(Kicked)` (or accept a `Bye(TimedOut)` on
clients) before a timeout drop.
Status: fixed in a33364e (host sends Bye(TimedOut) before every timeout drop, Pongs only seated peers; Bye(TimedOut) accepted; fake-Steam regression test, with and without the Bye arriving)

## F2 — Medium — A rejoin with the same SteamID is ignored while the host still holds the old seat
`src/Session.cpp:506-511`, `src/Session.cpp:750-756`

Scenario: over Steam the client's session ends without a `Bye` (it timed out the host after a host hitch or a one-way
outage: `Lose` only shuts down) and the game rejoins at once. Steam gives the host no event when a peer closes a
`ISteamNetworkingMessages` session, and the host read the old client's buffered pings, so the seat is still live. The
new session's `Hello` comes from the same, seated `PeerId` and is dropped as `Unexpected`; its pings keep refreshing
the stale seat's `LastHeard`.
Wrong result: the rejoin times out (`Lost(TimedOut)`, slot -1); with an automatic rejoin it never gets back in. Probe
(fake Steam semantics): 30 s of immediate rejoins after a 6 s host hitch, 7 handshake timeouts, host still lists 2
seated. Suspected on real Steam only insofar as it depends on Valve's documented "no notification when a peer
proactively closes the session".
Fix: on the host, treat a `Hello` from a seated peer as that seat leaving (`Left`, `SeatLeft`) followed by a fresh
`Hello`; also send a best-effort `Bye` from `Lose`.
Status: fixed in 13ad7af (a Hello from a seated peer frees the seat, then joins fresh; fake-Steam rejoin test). Not done: a Bye from `Lose`, because the host would then ignore the SteamID for 1 s and swallow an immediate rejoin's Hello, which this fix seats at once

## F3 — Medium — `isAlive` does not keep a Session-owned SteamTransport off a shut-down Steam
`steam/SteamTransport.cpp:138-160`, `steam/SteamTransport.h:26-28`, `steam/README.md:13`

Scenario: a game follows the documented alternative ("or pass `isAlive`") and its `Session` outlives
`SteamAPI_Shutdown()` (destroyed later, or `Stop()` after shutdown). `~Session` -> `Stop()` sends a `Bye` to every
peer through `SteamTransport::Send`, which calls `SendMessageToUser` without checking `Alive()`; only `Close` is gated.
Wrong result: a call into the dead Steam interface at exit (likely a crash). Headstone escapes it only because
`OnDetach` stops the session before `SteamManager::Shutdown`, not because of `isAlive`.
Fix: return early from `Send`, `Poll` and `Disconnect` when `!Alive()`, and say in the README that the callbacks
still unregister in the destructor.
Status: fixed in 0b3c054 (with F7: `Create` returns null and `Send`/`Poll` do nothing while `isAlive` is false; README says the callbacks still unregister in the destructor; `DingoNet-SteamTests` on a fake `ISteamNetworkingMessages`, generated with `--steam-sdk`)

## F4 — Low — `Event::Transport` is always `Closed` on a client's `Left(TransportLost)` for another client
`src/Session.cpp:703-711`, `include/DingoNet/Session.h:101-102`

Scenario: client B is lost by the host with a reset; the host sends `SeatLeft(slot, TransportLost)` to client A.
`SeatLeft` carries no transport reason, so A's `Left` has `Leave == TransportLost` with `Transport == Closed`.
Wrong result: the contract "with `TransportLost`, `Event::Transport` holds the transport's `DisconnectReason`" does not
hold on clients; a game that shows "reset" vs "closed" shows "closed" for every remote loss.
Fix: document `Transport` as host-only (or add the reason to `SeatLeft` with a session-protocol bump).
Status: fixed in 41255b1 (documented: `Transport` is our own transport's, set on a host's `Left` and a client's `Lost`; carrying it in `SeatLeft` would need a session-protocol bump)

## F5 — Low — A parting game message sent just before `Stop()` never reaches the host
`src/Session.cpp:741`, `include/DingoNet/Session.h:135-136`

Scenario: a client sends a reliable game message (final stats, chat) and calls `Stop()`. Both arrive in one host
`Poll`; the message is queued, then the `Bye` runs `DropPeer`, which erases every queued message of that slot.
Wrong result: the message is lost deterministically although the transport delivered it in order; documented, but it
contradicts the transport-level "what we sent before it still arrives" a second game will rely on.
Fix: tag `Message` and `Event` with a per-seat generation instead of erasing, so the game can tell a leaver's last
messages from the next occupant's.
Status: fixed in 94b7f9e (instead of a generation tag: the leaver's queued messages move onto its `Left` as `Event::LastMessages`, so a game that ignores the field behaves as before)

## F6 — Low — TCP's connection cap is below `MaxSlots` and is held by idle sockets
`src/TcpTransport.cpp:279-286`, `include/DingoNet/TcpTransport.h:97`

Scenario: a game sets `MaxSlots = 32` over TCP; the 17th client is accepted and closed at once by the 16-connection
default. Or a LAN peer opens 16 idle connections and re-opens each when the 5 s handshake timeout drops it.
Wrong result: legitimate joiners see `Connected` then `Lost(TransportLost, Closed)` ("connection lost"), not
`Rejected(Full)`, and can be locked out by idle sockets.
Fix: size `MaxConnections` from `MaxSlots` plus a handshake margin by default, and log the cap in the session's reject
path.
Status: fixed in 659ea82 (`MaxConnections` defaults to 64 = 31 clients + 16 handshakes; a host keeps at most 16 connections waiting for a Hello and hangs up on the oldest; tests: a full 32-seat TCP session with the 32nd joiner `Rejected(Full)`, 70 idle sockets then a joiner)

## F7 — Low — `SteamTransport::Close` does not close the transport
`steam/SteamTransport.cpp:220-227`, `steam/SteamTransport.cpp:162-210`

Scenario: a game (or tool) calls `Close()` and keeps polling, as it may with TCP and Loopback, whose `Poll` is inert
after `Close`. Steam's `Poll` still receives, re-announces any allowed or host peer as `Connected` and delivers its
packets; `Send` still reopens sessions (`AutoRestartBrokenSession`); `Pending` events survive.
Wrong result: peers reappear on a closed transport; the `Transport` contract differs per implementation.
Fix: set a closed flag in `Close` (clear `Pending`) and make `Send`/`Poll`/`Disconnect` no-ops after it.
Status: fixed in 0b3c054 (closed flag; `Close` clears pending events; `Send`/`Poll`/`Disconnect` and the session-request callback are no-ops after it)

## F8 — Low — The Windows scripts pause when run without arguments from PowerShell
`scripts/windows/Build.bat:22,27`, `Generate.bat:9`, `Package.bat:49,94`, `Test.bat:12,17`

Scenario: `.\scripts\windows\Build.bat` from PowerShell (or any `& script.bat` with no arguments). PowerShell starts
`cmd.exe /c ""<full path>\Build.bat""`, so `%CMDCMDLINE%` holds the full path, exactly the Explorer signature.
Verified with a copy of the check: it prints `WOULD-PAUSE` from PowerShell.
Wrong result: the "shells and CI never hang on them" claim in `CLAUDE.md` is false for PowerShell; an interactive run
waits for a key (CI passes arguments, so it is unaffected).
Fix: drop the automatic pause (or make it opt-in), since Explorer's and PowerShell's command lines differ only in a
trailing `" "`, too fragile to key on.
Status: fixed in 9a50ec7 (kept the pause, keyed on the parent process: it pauses only when the cmd.exe running it has explorer.exe as its parent; checked from PowerShell and from an Explorer launch)

## F9 — Low — The Linux package is not position-independent for shared objects
`premake5.lua:44-47`

Scenario: a game or a future DingoEngine module links `libDingoNet.a` into a `.so`. The objects are built without
`-fPIC` (Ubuntu's default `-fPIE` suits executables only).
Wrong result: link error "relocation ... can not be used when making a shared object; recompile with -fPIC".
Fix: `pic "On"` in the `DingoNet` project (no cost on x86-64 worth measuring).
Status: fixed in 708f920 (`pic "On"`; confirmed: the old Debug/Release `.a` fail to link into a `.so` with the R_X86_64_TPOFF32 error, the new ones link)

## F10 — Low — Test gaps on the paths that broke above
`tests/`

No test covers: a transport whose `Disconnect` is silent on the wire (F1, F2; a fake `Transport` with Steam's semantics
needs no SDK), `SteamTransport` at all (a fake `ISteamNetworkingMessages`), TCP's `MaxQueuedBytes` "not reading"
drop, `ConnectTimeout` against a black-holed address, and `CloseLinger` expiring on a peer that never sends its FIN.
Fix: add the fake-Steam session tests first; the TCP cap tests can use the existing `RawClient`.
Status: fixed in 4312a5c (not-reading drop, connect timeout against 192.0.2.1, close linger); the fake-Steam session tests came with a33364e and 13ad7af, the SteamTransport tests with 0b3c054

## Checked and correct
- TCP framing (4-byte LE length, partial frames across reads, budget-capped reads, incoming oversize frame -> `Error`),
  partial sends, the 4 MB queue check after flush, read-before-send, `Disconnect` linger (flush, shut, drain to FIN,
  `CloseLinger` cap), `Close`'s shared 0.25 s flush, connect-now-failed reported through `Poll`, connect timeout.
- Socket layer: CLOEXEC/`accept4`/`WSA_FLAG_NO_HANDLE_INHERIT` + `SetHandleInformation`, `MSG_NOSIGNAL`, `EINTR`
  retries (and the interrupted `connect` as in-progress), `PollConnect` on both OSes, one `SocketError` mapping,
  `WSAStartup` refcount under a mutex, failure paths releasing the library through the destructor.
- Windows `SO_EXCLUSIVEADDRUSE`: re-listening on the same fixed port right after a session (host or client closing
  first) succeeds. Host `Stop()` over TCP while a Windows client streams: the client read `Bye` in 60/60 trials.
- Session: handshake order and checks, MaxSlots clamp and adoption (larger host count -> `Rejected` + `Bye`), roster
  validation (range, duplicates, own slot), `Existing`, messages dropped with `Left`, slot reuse, deferred vs
  same-id-returning disconnects, stray-peer `Disconnect`, strict decoding, warn-once bitmask and the 32-strike kick,
  `UnseatedPacket` reply-then-hang-up, ping clamp, RTT smoothing and u32 wrap (future pong ignored), monotonic clock.
- Conditioner: reliable order under jitter, a clock jumping back with nothing held, held packets released on
  `Disconnect`/`Close` and dropped for a lost peer; Loopback ordering, refusal and parting packets.
- Bytes: bounds, sticky failure, LE on any host, NaN/inf/edge quantizers (Angle wrap at 360 masked to 0).
- Public headers: no Windows.h macro names, no `-Wchanges-meaning` hazard (`Event::Transport` is in the nested
  class), no platform header; one CRT (`/MD[d]`), v143 lib into a v145 game is supported, no `/GL`.
- Packaging and release: zip layout matches `CLAUDE.md`, `BuildInfo.h` stamped and restored with a fresh timestamp,
  tag-vs-`VERSION` check, `release: published` plus dispatch with create-if-missing and `--clobber`.
